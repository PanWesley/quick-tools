# 生活账单轻量升级设计

**日期：** 2026-06-24
**状态：** 已确认

## 1. 目标

在不破坏“纯前端、本地优先、快速记账”定位的前提下，按以下顺序升级：

1. 数据安全中心
2. 定期账单与待确认流程
3. 月度预算
4. 智能消费洞察
5. 首页信息层级优化

首要原则是轻便自然。新增能力不新增主导航，不要求用户先完成复杂配置；默认界面只呈现当前最值得处理的一件事，高级选项按需展开。

## 2. 已有基础与设计依据

当前产品已具备 IndexedDB 本地存储、完整 JSON 导出、CSV/Excel 导入、PWA、标签层级、图表和移动端交互。本次不重写现有账单核心，而是在既有模型和设置页上渐进增强。

纯浏览器本地数据仍可能因用户清除站点数据而丢失。Actual Budget 对纯浏览器模式也明确提示需要主动备份；浏览器可通过 `navigator.storage.persist()` 降低存储压力下被自动清理的风险，但不能防止用户主动清除数据。因此，“持久存储申请 + 外部备份”必须同时存在。

参考：

- [Actual Budget：本地浏览器安装与备份风险](https://actualbudget.org/docs/install/)
- [Actual Budget：Local-first 设计](https://actualbudget.org/docs/vision)
- [MDN：StorageManager.persist()](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist)
- [web.dev：Persistent storage](https://web.dev/articles/persistent-storage)
- [MDN：showSaveFilePicker()](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)
- [YNAB：预算目标、同步与报告能力](https://www.ynab.com/features)

## 3. 信息架构

保留现有四个底部入口：

- **概览：** 本月支出、预算进度、一个最高优先级提醒、简化图表
- **明细：** 正式账单与待确认账单
- **记账：** 保持当前快速录入流程
- **标签：** 保持现有标签管理

设置入口继续位于页面右上角，承载：

- 数据安全中心
- 定期账单管理
- 月度预算设置
- 现有外观、演示、反馈和危险操作

不新增独立分析中心。用户点击首页洞察后，再展开相关明细或图表。

## 4. 数据安全中心

### 4.1 默认界面

将现有“数据导出”和备份恢复能力整合为一个卡片：

- 状态：`数据安全 · 4 天前已备份`
- 主操作：`立即备份`
- 次操作：`恢复备份`
- 折叠入口：`更多选项`

“更多选项”内包含指定文件自动保存、加密备份、CSV 导出和存储保护状态。CSV 是数据交换格式，不作为完整恢复备份。

### 4.2 普通备份

默认生成可读 JSON，包含：

- `formatVersion`
- `databaseVersion`
- `appVersion`
- `exportedAt`
- `expenses`
- `tags`
- `tagGroups`
- `settings`
- 后续新增的 `recurringRules`、`pendingExpenses` 和 `budgets`

成功下载后记录：

- 上次成功备份时间
- 备份时正式账单数量
- 自上次备份后新增的正式账单数量

### 4.3 提醒规则

满足任一条件时提醒：

- 距上次成功备份达到 14 天
- 自上次成功备份后新增正式账单达到 30 笔

提醒表现为首页顶部轻量卡片，提供“立即备份”和“稍后”。“稍后”只延后本次提示，不修改阈值。数据正常且未达到阈值时，首页不显示备份模块。

### 4.4 指定文件自动保存

支持 `showSaveFilePicker()` 的浏览器可由用户主动选择一个 JSON 文件。数据发生变化后使用防抖写入，避免每次输入都触发磁盘操作。

规则：

- 首次绑定文件必须由用户手势触发
- 写入前检查权限
- 权限失效、浏览器不支持或写入失败时，降级为普通备份提醒
- 自动保存失败不得阻塞记账
- 界面明确显示“自动保存正常”或“需要重新授权”

因该 API 并非所有主流浏览器都支持，普通下载始终是基线方案。

### 4.5 存储保护

在用户首次成功保存真实账单或开启数据安全中心时，请求 `navigator.storage.persist()`。不在页面初始化时弹出权限请求。

设置页展示结果：

- 已获得持久存储
- 浏览器未授予
- 当前浏览器不支持

该能力只降低浏览器自动驱逐数据的概率，不使用“永不丢失”等绝对表述。

### 4.6 可选加密备份

普通 JSON 为默认方式。用户可主动选择“创建加密备份”：

- 输入密码并二次确认
- 使用 Web Crypto 派生密钥并进行认证加密
- 文件保存算法、盐、随机数和密文，不保存密码
- 恢复时必须输入原密码
- 明确提示密码不可找回

加密属于高级功能，默认折叠，不影响普通用户的一键备份路径。

### 4.7 恢复流程

1. 读取文件并验证结构、版本和必需字段
2. 在当前浏览器中建立临时安全快照
3. 展示备份时间、正式账单数、标签数和潜在冲突数
4. 选择“覆盖恢复”或“合并去重”
5. 写入后重新读取并校验数量与引用完整性
6. 失败时自动回滚安全快照，并提供重试或取消

覆盖模式清空受管理的数据表后导入。合并模式优先按稳定 ID 去重；缺少稳定 ID 的旧数据使用规范化后的日期、金额、项目名称和标签集合生成指纹。冲突记录默认保留当前数据，并在结果摘要中报告。

“清除所有数据”操作执行前也自动创建短期安全快照，当前会话内允许撤销。

## 5. 定期账单与待确认流程

### 5.1 定期规则

新增定期账单规则，字段包括：

```js
{
  id,
  name,
  estimatedAmount,
  frequency,        // weekly | monthly | yearly
  interval,
  nextDueDate,
  tagIds,
  note,
  active,
  createdAt,
  updatedAt
}
```

首版只支持每周、每月和每年，不加入复杂 cron、工作日顺延或自动扣款识别。

### 5.2 生成方式

定期规则到期后只生成待确认账单，不直接计入支出：

```js
{
  id,
  recurringRuleId,
  occurrenceKey,   // ruleId + 计划日期，保证每周期唯一
  scheduledDate,
  amount,
  tagIds,
  note,
  status,          // pending | confirmed | skipped
  createdAt,
  resolvedAt
}
```

页面启动、切回前台或进入概览时检查到期规则。每个周期通过 `occurrenceKey` 最多生成一次，过期未处理时不会重复生成。

### 5.3 展示与操作

- 概览页最多显示一条摘要：`3 笔定期账单待确认`
- 明细页增加“全部 / 待确认”切换
- 单项确认前可修改金额、日期和标签
- 支持批量确认
- 支持“跳过本期”
- 修改规则只影响未来周期
- 删除规则不删除已确认的历史账单

只有确认后，记录才写入正式账单表并参与预算、统计和图表。

## 6. 预算

### 6.1 配置

首版首次只询问月总预算。用户可跳过，跳过后不显示空预算卡片，也不反复催促。

分类预算放在“按分类设置”折叠区域中，按消费类型标签或标签组配置。分类预算之和可以高于月总预算，但界面给出轻量提示，不阻止保存。

```js
{
  month,            // YYYY-MM
  totalLimit,
  categoryLimits,   // [{ tagId, limit }]
  updatedAt
}
```

默认沿用最近一个月的预算配置，用户可修改当月数值。

### 6.2 首页表现

设置预算后显示一行进度：

`本月已用 68% · 剩余 ¥1,920`

接近或超过预算时改变状态和文案，但避免大面积警示色。待确认账单不计入已支出，可在详情中单独显示“待确认预计金额”。

## 7. 智能洞察

首页同时最多展示一条洞察，优先级如下：

1. 已超出或即将超出预算
2. 存在待确认定期账单
3. 分类支出明显高于平常
4. 本月与上月变化

首版规则保持可解释：

- 某分类本月支出高于过去三个完整月份平均值 50%
- 单笔金额处于该分类历史较高区间
- 历史数据不足时不生成异常结论

文案必须包含原因，例如：

`本月餐饮 ¥860，比近三个月平均高 58%`

用户可以关闭某类洞察。关闭后只停用该类提醒，不删除数据。

## 8. 首页精简规则

- 预算进度是稳定信息，只占一行
- 动态提醒最多一条
- 提醒优先显示需要用户采取行动的内容
- 备份正常时不占首页空间
- 定期规则未到期时不占首页空间
- 高级设置默认折叠
- 不增加新的常驻悬浮按钮
- 现有图表优先减少重复信息，再考虑新增图表

## 9. 模块边界

为避免继续扩大现有 `app.js`：

- `backup-service.js`：备份格式、下载、文件写入、加密和恢复编排
- `backup-utils.js`：纯函数验证、迁移、指纹和合并
- `recurring-service.js`：规则计算和待确认记录生成
- `recurring-utils.js`：日期推进、周期唯一键等纯函数
- `budget-service.js`：预算读取、结转和使用率计算
- `insight-service.js`：洞察候选生成和优先级选择

`db.js` 负责 IndexedDB 表和原子操作；`app.js` 只做页面协调与渲染入口。UI 不直接实现备份合并、周期计算或异常判断。

## 10. 数据库升级

IndexedDB 升级新增：

- `recurringRules`
- `pendingExpenses`
- `budgets`
- 必要的备份元数据仍可存入现有 `settings`

升级过程只新增表，不改写现有支出和标签。旧 JSON 恢复时缺失新字段视为空集合。新 JSON 在旧版本应用中应被明确拒绝或提示升级，不静默丢弃未知数据。

## 11. 错误处理

- 备份下载失败：保留数据，显示可重试提示
- 指定文件权限失效：标记需重新授权并降级提醒
- 加密密码错误：不开始导入，不改变当前数据
- 文件结构损坏：指出无法验证的部分，不提供覆盖按钮
- 恢复写入失败：回滚安全快照
- 定期账单生成失败：下次进入页面可幂等重试
- 洞察计算失败：隐藏洞察，不影响概览和记账
- 存储空间不足：提示立即导出，并停止非必要缓存写入

## 12. 测试标准

### 数据安全

- 普通 JSON 包含全部数据表和版本元数据
- 14 天与 30 笔两个阈值均能独立触发
- 自动文件写入失败后不影响新增账单
- 加密文件使用错误密码无法恢复
- 覆盖、合并和回滚分别有测试
- 合并去重对稳定 ID 和旧数据指纹均有效
- 恢复后标签引用和标签分组完整

### 定期账单

- 周、月、年规则正确推进日期
- 同一周期不会重复生成
- 待确认记录不进入统计
- 确认后只生成一条正式账单
- 跳过本期后可正常生成下一期
- 修改和删除规则不改变历史账单

### 预算与洞察

- 月总预算使用率与剩余金额正确
- 未设置预算时无空状态干扰
- 分类预算按标签正确汇总
- 数据不足时不生成异常
- 多条候选洞察只展示最高优先级一条

### 体验回归

- 桌面端和移动端均可完成一键普通备份
- 首页新增内容不造成明显首屏拥挤
- 记账路径和现有快捷键不增加步骤
- 离线状态下除首次外部库加载限制外，新功能可正常工作
- 键盘焦点、屏幕阅读器名称和减少动画设置保持可用

## 13. 实施顺序

1. 数据库升级与纯函数测试
2. 数据安全中心及恢复流程
3. 定期规则与待确认账单
4. 月总预算与可选分类预算
5. 洞察优先级与首页精简
6. 全量移动端、桌面端、PWA 和数据迁移回归

每一阶段独立可用并可单独发布。不得为了后续阶段提前在首页展示未完成入口。
