# Time 快捷编辑器 iOS 滚动锁修复设计

日期：2026-07-23  
状态：待用户书面确认

## 问题

在 iOS 真机打开“新建事项”并呼出键盘后，手指上下滑动仍会造成两种位移：

1. 顶部拖拽条的 `pointermove` 会给快捷编辑面板写入 `translateY`，允许把面板拖到键盘后方。
2. 文档级 `touchmove` 监听器在快捷编辑器打开时直接返回，没有阻止默认滚动，因此 iOS 仍可移动底层页面或产生橡皮筋滚动。

`body { position: fixed; overflow: hidden; }` 和 `inert` 只能锁住常规页面布局与交互，不能单独保证 iOS 键盘视口中的触摸滚动不发生。

## 目标行为

- 新建或编辑事项的主输入态打开后，单指上下滑动不移动面板，也不移动底层页面。
- 顶部短横线保留为视觉层级提示，但不再支持拖拽或下滑关闭。
- 点击遮罩、保存、键盘 Escape/返回链路仍可正常退出。
- 日期、提醒、重复等需要滚动的替换面板继续允许其内部滚动。
- 全屏详情及滚轮选择器维持原有内部滚动行为。
- 关闭编辑器后恢复页面原来的滚动位置与触摸行为。

## 方案

采用已批准的方案 A：

1. 删除快捷面板拖拽会话及 `pointerdown/pointermove/pointerup/pointercancel` 绑定，不再写入 `--quick-drag-offset` 或 `.is-dragging`。
2. 将拖拽条保留为纯装饰元素；移除与拖拽相关的 CSS 位移状态。
3. 在现有非被动 `touchmove` 入口中增加快捷编辑器主输入态保护：
   - 快捷编辑器关闭：维持现有任务左滑逻辑。
   - 快捷编辑器打开且处于键盘主输入态：调用 `preventDefault()`，阻止页面和视口平移。
   - 快捷编辑器处于日期/提醒/重复等替换面板或全屏详情：不做全局拦截，由对应内部滚动容器处理。
4. 保留现有 `body.quick-editor-open` 固定定位、滚动位置记录/恢复和背景 `inert`，形成布局锁、触摸锁和交互锁三层保护。

## 真机验收

桌面浏览器无法真实模拟 iOS 软件键盘与橡皮筋滚动。合入前自动化与浏览器验证完成后，仍需在 iPhone 上执行：

1. 打开新建事项并确认键盘出现。
2. 在输入区、工具栏、拖拽条和遮罩附近分别上下滑动。
3. 确认面板与底层页面均保持固定。
4. 打开日期面板，确认日期内容在确有溢出时仍能内部滚动。
