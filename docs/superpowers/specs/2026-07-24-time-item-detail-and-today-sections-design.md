# Time 事项详情与今日分组设计

状态：已获用户确认
日期：2026-07-24
基线：`origin/main`（已包含 PR #20）

## 背景

当前事项列表已经支持勾选、左滑编辑和删除，但点击条目主体不会进入此前完成的全屏详细编辑页。今日页把所有日期早于或等于今天的任务放在同一列表，因此逾期任务混入今日；已完成任务也仅排在待办之后，没有清晰分区。习惯虽然会保存背景色 `tone`，但今日、日期详情和清单的习惯渲染没有应用该颜色，日历习惯条也固定为淡紫色。

用户选择复用现有全屏详情页的方案 A，并确认删除整条事项或整个习惯。最终补充要求为：

- 详情页右上角显示“…”更多菜单，删除位于菜单内；
- 详情页不在顶部显示保存按钮；
- 用户滚动到详情内容底部后，通过底部“完成”按钮保存。

## 目标

- 点击任务或习惯条目主体，直接进入全屏详细编辑页，不先显示快捷面板或呼出键盘。
- 详情页底部提供“完成”主按钮，保存成功后关闭详情并返回来源页面。
- 详情页右上角“…”菜单提供删除，并在二次确认后删除整个任务或归档整个习惯。
- 今日页仅显示日期范围包含今天的任务，不显示已经结束的逾期任务。
- 今日任务明确分为“待办事项”和“已完成”，习惯继续使用独立“习惯打卡”分区。
- 习惯保存的背景色在今日、日期详情、清单和日历条目中一致体现。
- 今日页顶部统计与新筛选规则保持一致。

## 非目标

- 不新增只读详情页，不维护第二套详情 UI。
- 不支持“只删除本次重复”或“删除未来重复实例”；当前数据模型以一个习惯记录表示整组重复习惯。
- 不物理删除任务；任务继续进入现有“已删除”清单，允许恢复。
- 不删除习惯历史打卡记录；归档习惯后历史记录仍保留在本地数据和导出中。
- 不改变快捷新增面板和日期事务交互。
- 不重构日历、清单或数据库的无关功能。

## 选定方案

### 1. 条目点击进入全屏详情

任务和习惯的可点击主体统一携带明确的实体类型和实体 ID。以下区域点击后直接打开全屏详情：

- 今日页的待办任务、已完成任务和习惯；
- 日历日期详情中的任务和习惯；
- 清单页中的任务和习惯；
- 日历日期弹窗中的同类条目。

以下交互不触发详情：

- 完成、取消完成、打卡、跳过和重置按钮；
- 左滑操作按钮；
- 正在进行的横向滑动手势；
- 已删除清单中的恢复和彻底删除操作。

条目主体支持键盘聚焦，Enter 和 Space 与点击行为相同。打开详情时直接初始化编辑草稿、锁定背景并渲染全屏详情，不短暂显示快捷输入面板，也不主动聚焦文本框或呼出软件键盘。

### 2. 详情页导航与保存

详情页顶部保留：

- 左侧返回按钮；
- 中间“编辑事项”或“编辑习惯”标题；
- 右侧“…”更多按钮。

顶部不显示“完成”。标题、备注、日期时间、优先级、项目、重复、提醒和背景色沿用现有详细编辑能力。详情内容底部追加一个宽度充足、点击目标至少 44px 高的“完成”主按钮；按钮属于正常滚动内容，不固定悬浮，用户滑动到底部后才能看到。

点击底部“完成”：

1. 同步详情页输入到统一事项草稿；
2. 执行现有标题和日期时间校验；
3. 校验失败时停留在详情页并显示现有提示；
4. 校验成功时更新任务或习惯；
5. 重新载入数据，关闭整个编辑会话并返回打开详情前的页面。

点击顶部返回：

- 不写入数据库；
- 丢弃本次详情会话的未保存修改；
- 关闭整个编辑会话并回到来源页面；
- 不返回快捷输入面板，不呼出键盘。

从快捷新增或快捷编辑中的“详细信息”进入详情时，维持原有嵌套行为：返回快捷面板，底部“完成”只确认详情草稿并返回快捷面板，最后仍由快捷面板的发送按钮保存。直接从条目进入时才执行“保存并关闭”。

### 3. 更多菜单与删除

点击右上角“…”后，在按钮附近打开一个小型菜单，菜单仅包含当前需要的破坏性操作“删除”。菜单具备以下行为：

- 点击菜单外、按 Escape 或完成删除后关闭；
- 删除按钮使用危险色和明确文本；
- 焦点可从更多按钮进入菜单，并在菜单关闭后合理恢复；
- 菜单不会触发底层详情字段。

任务删除确认文案明确“删除后可在已删除清单恢复”。确认后调用现有软删除逻辑，把状态更新为 `deleted`。

习惯删除确认文案明确“将删除整个习惯，但保留历史打卡记录”。确认后把习惯状态更新为 `archived`，不删除 `habitLogs`。归档习惯从今日、日历、清单和通知计划中消失。

删除成功后关闭详情、重新载入数据并显示结果提示；取消确认则保持详情页不变。

### 4. 今日任务筛选与分组

今日任务使用统一选择器判断任务是否覆盖今天：

- 任务未删除；
- `date <= todayKey <= endDate`；
- 未设置有效 `endDate` 时使用 `date` 作为结束日期。

因此，昨天已经结束的任务不显示；从昨天持续到今天的日期范围任务仍属于今日。

筛选结果分成：

1. `status !== completed` 的“待办事项”；
2. `status === completed` 的“已完成”。

待办区始终保留；为空时显示“今天没有待办”。已完成区仅在有完成任务时显示，避免空标题占用空间。排序沿用创建时间的稳定顺序，并可在已有时间字段可用时保持现有日期内排序。

页面顺序固定为：

1. 待办事项；
2. 已完成；
3. 习惯打卡；
4. 今日一句（若启用）。

顶部摘要只统计上述今日任务和今天到期的习惯，不再把逾期任务计入“待完成”或“已完成”。

### 5. 习惯背景色

习惯渲染统一读取 `habit.tone`。合法颜色通过受控颜色表映射为 CSS 自定义属性，不直接拼接任意用户输入。条目使用该颜色生成柔和背景、边框和左侧强调线：

- 今日习惯；
- 日期详情习惯；
- 清单习惯；
- 日历中的习惯条。

未设置颜色时使用现有默认淡紫色。完成、跳过或已打卡状态只调整透明度、图标和文字，不覆盖用户颜色。任务现有颜色行为保持不变；同一颜色表中的所有可选颜色都应有渲染结果，避免只有早期十种颜色生效。

## 状态与组件边界

### 今日选择器

在 `app-state.js` 中提供纯函数，以便渲染器、标题统计和测试共享：

- 选择日期范围包含今天且未删除的任务；
- 分割待办与已完成任务。

页面不再自行复制 `date <= todayKey` 条件。

### 详情入口模式

编辑器会话记录入口为 `quick` 或 `item-detail`：

- `quick`：保持现有详情返回快捷面板的路径；
- `item-detail`：返回关闭整个会话，底部完成保存并关闭。

任务和习惯数据填充抽成不负责打开 UI 的初始化步骤，避免“先打开快捷面板，再切详情页”造成键盘闪动。详情页仍复用统一草稿、日期事务和保存 payload。

### 删除持久化

数据库层新增习惯归档方法，通过现有 `writeWithOp` 写入习惯记录与操作日志。任务继续使用已有 `deleteTask`。页面控制器只负责确认、调用、刷新与关闭，不直接修改内存数据。

## 滚动、焦点与手势

- 详情页保持自身纵向滚动；底层页面保持 `inert` 和滚动锁定。
- 底部完成按钮位于详情滚动内容末尾，并为 iPhone 安全区保留底部间距。
- 条目点击与左滑通过手势位移阈值区分；完成一次横滑后不误开详情。
- 打开详情后初始焦点进入顶部返回按钮或详情对话框，不进入标题输入。
- 更多菜单打开时焦点进入删除项；关闭后回到更多按钮。
- 详情关闭后焦点尽可能回到原条目；若原条目已被删除，则回到该页面的稳定容器或新增按钮。

## 无障碍

- 可点击条目具有按钮语义、可聚焦，并提供“编辑任务/编辑习惯”的可访问名称。
- “…”按钮具有“更多操作”标签及 `aria-expanded`、`aria-controls`。
- 更多菜单使用菜单或等价的可访问弹出结构，删除项不只依赖红色表达风险。
- 底部“完成”按钮至少 44px 高，文本明确。
- 动态出现的“已完成”分区保持正确标题层级。
- 删除结果通过现有 toast 告知；确认取消不改变焦点上下文。

## 错误处理

- 条目对应实体不存在：不打开空详情，显示“没有找到这条任务/这个习惯”。
- 保存校验失败：停留详情并保留草稿。
- 数据库保存或删除失败：详情保持打开，显示错误信息，允许重试。
- 删除已被其他操作删除的任务：重新载入数据并安全关闭详情。
- 非法或未知 `tone`：回退默认淡紫色，不生成任意内联 CSS。
- 习惯归档后通知刷新失败：沿用现有“本地数据成功、通知同步非阻塞”的处理，不回滚已确认归档。

## 测试策略

### 状态单元测试

- 今日选择器排除昨天已经结束的逾期任务。
- 今日选择器包含跨日范围覆盖今天的任务。
- 今日分组把 active 与 completed 分开并排除 deleted。
- 归档习惯不再被 `habitDueOn` 选中。
- 日历习惯条目携带 `tone`。

### 数据库测试

- 归档习惯写入 `status: archived`，保留原记录字段。
- 归档不删除任何 `habitLogs`。
- 操作日志记录习惯归档。

### 编辑器运行时测试

- 点击条目主体直接打开详情且不显示快捷面板、不聚焦标题。
- 交互按钮和横滑不会误开详情。
- 直接详情底部完成保存并关闭。
- 直接详情返回丢弃修改并关闭，不显示键盘。
- 快捷入口详情仍返回快捷面板。
- 更多菜单可打开、Escape 关闭。
- 任务删除调用软删除；习惯删除调用归档；失败时详情保持打开。

### 渲染与契约测试

- 今日页具有独立的待办和已完成容器。
- 已完成为空时分区隐藏。
- 今日标题统计使用同一今日选择器。
- 所有习惯条目渲染 `tone`，未知值回退默认色。
- 详情顶部为更多按钮，底部为完成按钮，点击目标满足 44px。
- Service Worker 与静态资源缓存版本同步更新。

### 浏览器验收

在 390×844 视口验证：

- 今日页不显示已结束的逾期任务；
- 待办、已完成和习惯分区清晰且间距舒适；
- 点击任务和习惯直接打开全屏详情，无快捷面板或键盘闪动；
- 滚动到底部可见完整“完成”按钮；
- 右上角更多菜单和二次确认可用；
- 选择的习惯颜色在今日、日历、日期详情和清单一致；
- 返回、保存、删除后没有滚动穿透或焦点丢失。
